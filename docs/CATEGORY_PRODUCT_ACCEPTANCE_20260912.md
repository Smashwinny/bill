# 分类产品验收与皮肤交付（2026-09-12）

## 结论

**分类验收不通过。** 当前问题不是缺少几个按钮，而是新建账单、编辑账单、分类管理和分析统计使用了不同的分类来源。金额与记录完整，不代表分类流程正确。此次只交付用户另行要求的图标与配色皮肤，不将分类问题标记为已修复。

验收基线是提交 `d4d11f4`、手机上的 `com.hulk.manualledger` v20。分类逻辑在本次皮肤版本中没有修改。真机数据库与产品用例共 10 项：6 项通过、4 项失败。失败均有可重复执行的断言，不是只凭页面观感判断。

## 已复现的阻断问题

### P1：只改备注也可能改掉账单分类

准备“饮食 › 早餐”账单，将“早餐”移为一级分类，再在编辑流水中仅改备注并保存。期望分类仍为“早餐”，实际变成“饮食 › 未细分”。

`ManualLedgerData.kt` 的 `update()` 将不带层级分隔符的分类重新送入 `CategoryCatalog.normalize()`，清空分类 ID 后又重建绑定。产品要求：编辑非分类字段不得改变分类；应保存用户明确选择的分类 ID，不能用别名推断覆盖用户选择。

证据：`ProductCategoryAcceptanceTest.editingOnlyNoteMustKeepPromotedCategory`，真机断言失败。

### P1：管理中删除的预设分类仍被新记账提供

删除“早餐”后，数据库分类树确实不再包含该节点；新记账入口仍从 `CategoryCatalog.hierarchyOptions()` 读取预设“早餐”。保存该路径又可通过 `ensureCategoryTree()` 建回分类。

产品要求：新增、编辑、管理都只从同一份有效分类树选择；删除后的节点不能继续出现在新建选项中。历史导入若出现旧路径，应明确提示处理方式，不能隐式复活。

证据：`deletedBuiltInMustDisappearFromNewEntryOptions` 真机失败；`HierarchicalCategoryPicker()` 的预设、历史路径、SharedPreferences 合并逻辑与数据库分类树并存。

### P1：移动分类不一定改变统计归属

将“早餐”移动到“购物”下面。账单路径正确变为“购物 › 早餐”，分析默认归类仍得到“饮食”。

原因：`resolveCategory()` 使用额外的归类映射和别名规范化，而非按真实分类节点向上聚合。产品要求：默认统计遵从用户管理的分类树；若提供独立报表分组，应明确命名，并让用户知道它与账单分类的差别。

证据：`analysisMustRespectMovedCategoryRoot` 真机失败，期望“购物”，实际“饮食”。

### P1：“备份”不能完整保存分类设置

新建没有账单的自定义分类后导出，导出内容不包含这个分类。`ManualLedgerMigrationCodec.exportJson()` 只输出 transactions，没有完整分类树、空分类或分析映射。

产品要求：将当前功能准确命名为流水导出，或提供包含分类树与必要设置、可校验并可恢复的完整备份。未通过完整恢复演练前，不能据此承诺分类配置恢复。

证据：`backupMustIncludeEmptyCustomCategory` 真机失败。此次数据保护使用直接数据库快照，未依赖应用的流水导出。

## 其他产品缺口（代码确认，未全部进行写入式 UI 复现）

- **P1，分类管理不成闭环：** `CategoryTreeManagerDialog()` 提供拖动、合并、删除，没有新增一级分类或重命名入口；新建页只允许在既有一级分类下添加二级分类。用户无法在一个管理入口完成创建、使用、整理全过程。
- **P1，深层同名分类难以区分：** 数据库和拖动支持三级及以上；`LeafCategoryDialog()` 只按根节点聚合并显示叶子名称，仍称“二级分类”。应显示完整路径或逐级浏览。本次快照最大深度为 3；没有发现同一根下同名叶子的现有样本，所以此项为潜在场景缺陷，不声称已有账单选错。
- **P1，拖动会直接重写历史路径：** 除同名合并外，移动没有事前影响预览；跨长列表也没有目标选择器。应提供“移动到…”、受影响记录数量、取消与明确确认；不要让长按拖拽成为唯一方法。
- **P1，同步文案超出已实现范围：** 当前同步事件承载账单路径，没有独立的分类配置事件；空分类和无账单的树调整无法据此传到其他设备。云端往返和多设备分类一致性本次未联网测试。
- **P1，账单编辑字段不完整：** `EditTransactionDialog()` 没有传回原 `targetAccount`，`update()` 会写入默认 null。含目标账户的转账账单需要独立回归，不能只以“金额没变”视为完整编辑通过。
- **P2，列表组织能力不足：** 分类树没有搜索、折叠或稳定的同级排序操作。196 个节点的账本中，单纯放入可滚动弹窗的使用成本较高。

## 建议的下一轮验收标准

1. 一份分类树贯穿新建、编辑、管理与默认报表；账单按 ID 绑定，名称和路径只用于显示。
2. 管理入口支持新增一级/子级、重命名、移动、删除或停用；每项操作都解释对历史账单的影响。
3. 支持的最大层级明确；同名叶子可辨认，完整路径可查看，禁止循环、跨收支类型移动。
4. 编辑备注、账户、日期或金额时，其他字段逐项保持不变。
5. 删除不复活，导入旧路径有明确处理策略，取消所有写入确认时数据完全不变。
6. 报表分类金额和总支出一致；移动后的归属与管理树一致，不混用隐藏别名。
7. 全量备份恢复保留账单、空分类、分类关系、必要设置；离线和多设备场景单独验证。
